# 树与帐篷 求解器（v0.1.0）

「树与帐篷」（Tents and Trees）谜题的求解器。在格子里放树、填好每行每列的帐篷数量，程序会用人类常用的推理规则一步步推给你看；如果推不动，再自动试探，直到解出来。

支持 **4×4 到 20×20**，支持逐步回放、上一步 / 下一步 / 自动播放；界面提供**中文 / English** 双语，默认中文，点页面右上角的国旗按钮切换，选择会记在浏览器本地。功能包括：缺失数字模式（提示可填「?」）、棋盘代码导出 / 还原、本地截图识别（把游戏截图粘贴或选进来，自动认出树的位置和行 / 列提示数字，识别不准可在棋盘上手动修正）。

**在线预览**：https://yuyia2003.github.io/tents-and-trees-solver/

---

## 怎么打开

双击 `index.html` 即可，不需要装任何东西、不需要联网。

> `js/` 和 `css/` 两个文件夹必须和这个 html 文件放在同一层目录里，搬动时三个一起搬。
> 因为浏览器不允许本地打开的页面用 `import` 加载模块，所以这里用的是普通 `<script>` 标签，顺序在 html 末尾已经排好。

想验算算法是否正常，可以打开 `算法测试.html`，它会跑一遍所有示例题并显示结果。

## 文件结构（读代码就按这个顺序）

| 文件 | 干什么 | 新手从这里看 |
| --- | --- | --- |
| `js/core.js` | 基础数据：格子有四种状态（未定 / 帐篷 / 草地 / 树）、题目怎么变成"局面"、找邻居、检查题目填得对不对；行/列提示允许是 `null`（缺失数字，界面上显示「?」） | 先看这个，全是小工具函数 |
| `js/i18n.js` | 中英双语字典与切换：`t(key, vars)` 取当前语言文案，静态元素按 `data-i18n` 属性刷新，语言记在 localStorage | 改文案先查字典 |
| `js/rules.js` | 10 条推理规则，每条负责一种"人也会想到的技巧"，写法都是"扫描局面 → 能确定就改 → 返回改了哪几格" | 每条规则上都有注释说明道理 |
| `js/solver.js` | 主流程：先检查局面有没有矛盾，再反复套规则直到推不动；推不动就交给 backtrack.js | `TT.solve()` 是总入口 |
| `js/backtrack.js` | 回溯搜索：挑"候选最少的那棵树"假设一步，走不通就退回来换下一个 | 只解决"推理卡住之后"的问题 |
| `js/recognize.js` | 本地截图识别：网格投影定位行列（碎段过滤）、逐格判断树、连通域切数字；模板分两层——同款游戏截图切出的真实字形掩码为主，离屏 canvas 粗体字形兜底；褪色浅色笔画直接判 0；不联网、不调接口 | 只做识别，结果交给 app 载入 |
| `js/demos.js` | 6 道示例题的数据（6×6 / 8×8 / 16×16 / 17×17 / 18×18 / 20×20） | 纯数据，没有逻辑 |
| `js/render.js` | 把局面画到页面上：棋盘、提示数字、步骤卡片 | 只负责显示，不做推理 |
| `js/app.js` | 总开关：监听按钮、调用求解器、把结果交给 render 去画；还负责缺失模式开关、棋盘代码的编码 / 解码 / 校验 / 还原、截图识别的文件 / 剪贴板接入 | 想知道"点了按钮之后发生了什么"看这个 |
| `css/style.css` | 样式：颜色变量在最上面，改主题只改那 7 个色值 | 窄屏样式写在前面，宽屏在文件末尾 |
| `tools/` | 开发时用的小脚本（生成示例题、跑自检），不影响页面运行 | 可以不看 |
| `算法测试.html` | 测试页：跑所有示例题，逐项显示通过 / 失败 | 改完代码先开这个 |

数据流向：`core` → `rules` → `solver` → `backtrack` 是计算链路，`demos` 提供题目，`render` + `app` 负责显示和交互。所有函数都挂在 `window.TT` 上（读作 Tree & Tent），不往全局乱丢变量。

## 和原版相比改了什么

**界面**
- 全部重画：白灰底 + 蓝绿点缀，棋盘用 CSS 网格，树和帐篷是内联 SVG（原来是 base64 PNG），放大不糊。
- 提示数字改成可编辑的输入框，填够 / 填超会变色。
- 新增步骤面板：每条规则的名称、一句话解释、本步改了哪几格（棋盘上用绿框标出来），带滑块、上一步 / 下一步 / 自动播放。
- 窄屏（手机 375px 起）单列排布，20×20 在手机上横向滚动，不会缩成点不中。
- 界面文案为中英双语（默认中文），包括错误提示；切换语言后步骤说明、状态条、按钮标题一并刷新。

**代码**
- 原版大量使用隐式全局变量（`errorMessage`、`rowEmptyCells`、`topCell` 等），出错时会污染其它功能；新版全部收进 `TT` 命名空间，每个文件一个 IIFE，`'use strict'`。
- 原版用拼接字符串再比较 HTML 来判断"这一轮有没有变化"，改一处样式就可能失效；新版规则直接返回改动坐标数组，变化与否是明确的布尔判断。
- 修掉原版几处真实错误：`emptyCell[0]` 应为 `emptyCell[i]`（少改了很多格子）、`isChanged |= isChanged |=` 重复赋值、`GroupAdjacentNumbers([])` 会产生 `[[undefined]]`、`checkIsValid` 里几个恒真的判断、出错时 `return result + "<br>error: "` 把错误塞进 HTML。
- 求解失败时给的是人话解释，不再是半截 HTML。

**能力**
- 尺寸上限从 18×18 提到 20×20。实测 20×20 纯推理解不出时必须试探，通常 0.3–0.7 秒内出解。
- 每步都做合法性校验，而且是按**配对**校验（见下节）：行/列配额、帐篷不能相邻、每顶帐篷都要挨着树、以及"这些树和这些帐篷还能不能两两配上对"（二分图匹配）。任何一条不成立就立刻停下并指出位置，不会默默算出错误答案。
- 回溯有节点数和时间双预算，超了会明确告诉你"没解出来"，不会假称有解。

**示例题**
- 第 1–5 道（6×6 / 8×8 / 16×16 / 17×17 / 18×18）就是**原版 index.html 里的那 5 道**，原样搬过来的 —— 用正确的配对规则检查，它们完全合法、答案唯一、连试探都不需要。
- 第 6 道 20×20 是新造的（原版没有这么大的题），同样验证过：题目合格、有解、解合法、答案唯一。
- 6 道题的验证结果都写在 `tools/make-demos.js` 的输出里，可以自己重跑一遍核对。

## 本轮新增的两个功能

### 1. 缺失数字模式

工具栏上有独立开关「缺失数字模式」。

- 打开后，每一行 / 每一列的提示都可以填「?」，表示这一行 / 列要几个帐篷**不知道**，数量不限；其余规则（帐篷不相邻、树帐一对一配对、挨着树等）完全不变。
- 刚打开时所有提示先置为「?」，只把题目里已知的数字填回去即可；关掉开关，「?」会归 0。
- 数据口径：提示数字在引擎里是**整数或 `null`**，`null` 就对应界面上的「?」。`core.js` 的 `createState` 原样透传 `null`；`solver.js` 的 `validate` / `isSolved`、`rules.js` 的四条配额规则遇到 `null` 行 / 列就跳过配额检查；不依赖配额的规则（草地排除、帐篷隔离、孤立树、配对等）照常工作。
- 状态条只按**行提示**算一次合计（行提示合计 = 帐篷总数 = 列提示合计，不能横竖相加，否则会翻倍）；行列合计不一致会单独提示，有「?」时不再提示"两个数字还没对上"。

### 2. 棋盘代码导出 / 还原

页面底部「棋盘代码」区块：文本框 + 三个按钮（生成代码 / 复制代码 / 粘贴还原）。

- **生成代码**：把当前棋盘写成一段紧凑字符串，内容包括尺寸、树的位置、行 / 列提示（「?」也一起保存）、当前格子标记、是否处于缺失模式。
- **复制代码**：把代码复制到剪贴板；剪贴板接口不可用时自动退成"选中文本框内容手动复制"。
- **粘贴还原**：把代码粘进文本框后点按钮，程序先做结构校验（尺寸 4×4 ~ 20×20、行列长度对得上、提示值合法、格子状态合法、树和标记一致），通过后重建整盘；不合法时给出中文提示，不会把坏数据画上去。
- 编码方式：`JSON → encodeURIComponent → base64url`（`+`/`/`/`=` 换成 URL 安全字符），代码在 `app.js` 的 `buildSnapshot / encodeSnapshot / decodeSnapshot / validateSnapshot` 这几个函数里，注释齐全。

页面区块顺序：**棋盘 → 截图识别 → 棋盘代码 → 规则说明**。「规则说明」按钮放在棋盘窗格右下角，点击折叠 / 展开最后那块规则面板。

## 截图识别

页面上「截图识别」区块，两种导入方式：

- **选择截图文件**：点按钮从电脑里挑一张游戏截图（PNG / JPG 等图片格式）。
- **从剪贴板粘贴**：先在游戏里截图复制，再点按钮；焦点不在输入框时，直接在页面上按 `Ctrl+V` 也能识别。

识别全程在浏览器本地完成，不上传图片、不调网络接口。识别对应的游戏为 [Tents and Trees](https://store.steampowered.com/app/2310810/)，链接展示在截图识别区块内。流程在 `js/recognize.js`：

1. 按深灰空格 + 浅绿树块的颜色做行列投影，定位棋盘每一格的位置；投影出的一两像素碎段（边框 / 阴影）按中位格宽过滤掉，尺寸自动识别，4×4 ~ 20×20。
2. 逐格统计绿色像素占比，超过阈值判为树，其余为空。
3. 在棋盘上方 / 左侧色带里用连通域切出数字笔画（窄的「1」也保留），归一化后比对模板：主模板是从同款游戏截图里切出的真实字形掩码，canvas 粗体字形只给样本里没出现过的数字兜底；笔画是褪色浅色的直接判 0；没把握的数字留空（界面显示「?」，自动进入缺失数字模式）。

识别结果载入既有编辑器：树位、提示数字都可以继续改——点格子切换树，点数字框改提示。四张同风格截图（7×7、9×9、17×17、20×20）回归对照：树位和数字全部识别正确。

> 识别阈值是按这几款同画风截图标定的；换了配色、字体或带干扰元素的截图，可能出现个别误判，载入后手动修正即可。

## 规则：为什么是"配对"而不是"独占"

这是这个程序最要紧的一条，也是旧版写错过的知识点：

- **正确的规则**：树和帐篷是**一对一配对**——每棵树配一顶帐篷（那顶就在它上下左右），每顶帐篷只属于一棵树；**但一顶帐篷旁边可以同时挨着好几棵树**，多出来的那些树只是"蹭在旁边"，它们各自还有自己配对的帐篷。
- **错误的写法（旧版）**：要求"帐篷旁边只能有一棵树、树旁边只能有一顶帐篷"。这会把它本来合法的题判成无解 —— 原版那 5 道题就是这样被冤枉的。

举例（这是原版 6×6 的第 3、4、5 行最左边那一列）：

```
树        ← 配的是下面第 1 行的帐篷
帐篷 A    ← A 同时挨着上面和下面两棵树，但它只属于上面那棵
树        ← 这棵树不归 A 管，它配的是右边自己的帐篷
```

所以判断答案对不对，不能去数"帐篷旁边有几棵树"，得看这些树和这些帐篷**能不能两两配上对**。程序里这件事由 `core.js` 的 `TT.matchAllTrees()` 做（二分图匹配 / 匈牙利算法），`solver.js` 的 `TT.validate()` 和 `TT.isSolved()` 都调它。

连带的两个后果，读代码时会遇到：
- 一顶帐篷挨着两棵树时，**不能**因此断定某棵树已经配好了；所以旧版那条"树已配好帐篷 → 它旁边其他格子都是草地"的规则是错的，已经删掉。
- 试探（`placeGuess`）只放帐篷、不把树的其他候选格标成草地 —— 那些格子可能是别的树的帐篷。

## 想改成自己的样子

- **换配色**：`css/style.css` 顶部 `:root` 里 7 个变量，改完整个页面跟着变。
- **加一道示例题**：在 `js/demos.js` 里照抄一条，`trees` 用 `T` 和 `.` 写棋盘，再填 `rowHints` / `colHints`。
- **加一条推理规则**：在 `js/rules.js` 里写一个 `apply(state)` 函数，返回 `{ changed, noteKey, vars }` 或 `null`，然后加进 `TT.RULES` 数组末尾（数组顺序就是调用顺序，快规则放前面）；规则名和备注文案在 `js/i18n.js` 字典里补对应 key。
- **换求解顺序**：`solver.js` 里 `propagate` 每轮都从第一条规则重新开始，想改优先级就调整 `TT.RULES` 的顺序。

## 已知限制

- 纯前端单页，不自动保存；刷新前可以用「棋盘代码」把当前棋盘导出成字符串，下次粘贴还原。
- 回溯搜索的预算是 30000 节点 / 3 秒。极少数刻意构造的病态题目可能超时，此时会提示"没解出来"，不会给错误答案。
- 不支持"标记想排除的格子"之类的草稿功能：编辑时点格子只在"树 / 空格"之间切换。
